Safe recovery sequence

  1. Download the chosen .dump or .tar.gz file and its matching .sha256.
  2. Verify the checksum after transfer.
  3. Create or select a temporary staging database and storage directory.
  4. Restore there first—never test directly against production.
  5. Run python tools/recovery_check.py and the production smoke test.
  6. Only after validation, switch production to the recovered database/storage or perform a controlled maintenance-window restore.
  7. Verify login, subscriptions, Stripe webhooks, alerts, dashboard data, and Forward Record.

No one-click production restore

NeuralTrend intentionally does not restore production data from a browser button. A database restore can overwrite newer users, subscriptions, simulations, and webhook records. Restoration must be performed through a controlled Render Shell or staging workflow.

Database restore command pattern

Use this only after selecting the correct target database and placing the downloaded dump in the controlled environment.

pg_restore --clean --if-exists --no-owner --no-acl \
  --dbname="$RESTORE_DATABASE_URL" \
  neuraltrend-postgres-YYYYMMDDTHHMMSSZ.dump

Forward Record restore pattern

mkdir -p /tmp/neuraltrend-forward-restore

tar -xzf neuraltrend-forward-record-YYYYMMDDTHHMMSSZ.tar.gz \
  -C /tmp/neuraltrend-forward-restore
